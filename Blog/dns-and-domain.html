域名和 DNS：你按下回车之后的三百毫秒

2026-09-14 · 网络系列 · 第一篇

你在地址栏敲下 www.example.com，回车，页面出来了。这中间发生了什么？大多数人会说"连上服务器了"。但真实过程比这有意思得多，而且理解它对你排错极有帮助——因为网站打不开的原因，一大半出在这一段里。

一、互联网只认数字，域名是给人看的

网络上每一台服务器都有一个 IP 地址，比如 93.184.216.34（IPv4）或者 2606:2800:220:1:248:1893:25c8:1946（IPv6）。IP 是门牌号，真正的路由全靠它。

但没有人记得住一长串数字，而且服务器换机房、换服务商时 IP 会变。所以有了域名：给 IP 起的人类友好的别名。

把域名翻译成 IP 的这套系统，就叫 DNS（Domain Name System，域名系统）。它是整个互联网最不起眼、但也最基础的一层——DNS 挂了，你记得住 IP 的网站还能开，其他全都打不开。

二、一个域名是怎么拆的

拿 www.4444442.xyz 举例，从右往左读：

  • .xyz —— 顶级域名（TLD）。类似的还有 .com、.cn、.top。
  • 4444442 —— 二级域名。这是你真正去注册局花钱买的那一段。
  • www —— 子域名（subdomain）。这一层不用花钱，你想加多少加多少。

所以买域名，严格说买的是某个顶级域名下面的一个二级域名的使用权，通常是按年租，不是买断。

子域名能干嘛

一个域名下可以挂无数个子域名，指向完全不同的服务器：

www.example.com    -> 主站
blog.example.com   -> 博客，可能托管在另一家
api.example.com    -> 接口服务
img.example.com    -> 图床
test.example.com   -> 测试环境
*.example.com      -> 泛解析：任何没单独配置的子域名都落到这里

这非常实用：一台服务器可以托管几十个网站，靠子域名区分。你现在看到这个博客，就是 4444442.xyz 下的一个路径，同一套域名体系里的事。

三、DNS 查询到底走了几步

浏览器要知道 www.example.com 的 IP，会按顺序问一圈，任何一步命中缓存就提前返回：

  1. 浏览器自己的缓存。刚访问过的域名，Chrome 自己记着。
  2. 操作系统的缓存。Windows 里可以 ipconfig /displaydns 看，ipconfig /flushdns 清。
  3. hosts 文件。本地手工写的对照表，优先级很高，常用来做屏蔽或者本地调试。
  4. 本地 DNS 服务器。通常是你路由器，或者运营商（电信/联通/移动）的 DNS。这一层是绝大多数家用场景的真正出口。
  5. 根域名服务器 → 顶级域名服务器 → 权威域名服务器。如果本地 DNS 也没有缓存，它会替你从根开始一层层问下去，最后拿到答案。

整个过程通常几十到几百毫秒。第一次访问慢，第二次快，就是因为缓存。

先记住这个：网站"昨天还好好的今天打不开，但手机流量能打开"——八成是本地 DNS 缓存或者运营商 DNS 出了问题，不是网站挂了。换 DNS（比如 223.5.5.5 阿里、119.29.29.29 腾讯）往往立刻见效。

四、几种常见的记录类型

在域名管理后台配置解析时，你会看到这些类型：

  • A 记录 —— 域名指向一个 IPv4 地址。最常用。
  • AAAA 记录 —— 指向 IPv6 地址。四个 A 是因为 IPv6 地址是 128 位，是 IPv4 的四倍。
  • CNAME 记录 —— 域名指向另一个域名，由对方去解析。常见于把子域名托管给云服务商。
  • MX 记录 —— 邮件服务器地址。收发邮件靠它。
  • TXT 记录 —— 存放文本，常用来做域名所有权验证、邮件防伪（SPF/DKIM）。
  • NS 记录 —— 指定这个域名由哪台服务器负责解析。改 NS 相当于"换 DNS 供应商"。

TTL 是什么

每条记录后面都跟着一个 TTL（Time To Live），单位是秒，表示这条解析结果可以被缓存多久。TTL=600 就是十分钟内别人问同一个域名，本地 DNS 直接用缓存，不再去问。

所以换服务器时有个经验：先把 TTL 调小（比如 60 秒），等生效后再改 IP，最后再调回去。否则 TTL 没到期，一部分用户还在访问老服务器。

五、动手看一下自己的域名解析

这几个命令很值得存起来：

nslookup www.example.com          # 最简单，看解析结果
nslookup www.example.com 8.8.8.8  # 指定用 8.8.8.8 去问
dig www.example.com +trace        # Linux/macOS：完整展示从根开始的查询链
ipconfig /flushdns                # Windows：清空本地 DNS 缓存
ping www.example.com              # 顺便能看到解析出的 IP

+trace 那个特别直观，它会一步步打印出根服务器、顶级域名服务器、权威服务器的回答。第一次看到的时候会觉得"原来是这样"。

六、DNS 是怎么被拿来做手脚的

DNS 设计于上世纪八十年代，那时候默认所有人都是善意的。它有两个天生的弱点：查询默认明文，而且基本不做来源验证。

由此衍生出一类攻击：

  • DNS 劫持/投毒。在链路上篡改应答，把你要访问的域名指向别的 IP。运营商插广告弹窗，就是这个原理的温和版本。
  • DNS 欺骗。攻击者在局域网内抢先应答伪造结果。所以公共 WiFi 上的 DNS 不可信。
  • 域名抢注与仿冒。注册 examp1e.com（数字 1 冒充字母 l）这类形近域名，配合证书骗人。

应对方式是加密查询：DoH（DNS over HTTPS）和 DoT（DNS over TLS），把查询包进加密通道，中间人看不到也改不了。

但要说清楚：加密 DNS 只是让别人看不到你在查什么，不改变"你能不能访问"这件事。这两件事经常被混为一谈。

七、HTTPS 里的域名：证书是绑在域名上的

你可能注意到地址栏的小锁。它背后的机制是 TLS 证书，而证书里有一项关键字段叫 Common Name / SAN，写明了这张证书对哪些域名有效。

所以：

  • 证书是签给 example.com 的，你用 example.net 访问就会报错。
  • 证书过期、域名不匹配、签发机构不受信任——浏览器会直接拦下来，给你一个吓人的红页面。
  • 免费证书（比如 Let's Encrypt）可以自动化签发，有效期三个月，所以现在"给一个域名配 HTTPS"基本是零成本、零门槛的事。

关于 HTTPS 和证书更细的机制，见同系列的另一篇。

八、自己搞一个网站，域名这块要做几件事

如果你以后想自己搭个站，域名相关的动作大致是：

  1. 注册域名。选一个短、好记、不容易打错的。注册商的续费价格比首年价格重要得多。
  2. 做实名认证。国内后缀（.cn 等）必须实名，否则会被停止解析。
  3. 配解析。在注册商后台加 A 记录或者 CNAME。
  4. 等生效。通常几分钟，慢的话几小时，取决于 TTL。
  5. 配 HTTPS。托管平台（GitHub Pages、Cloudflare Pages 这类）一般一键搞定。
容易被忽略的一点：域名是有到期日的。忘了续费，解析会被停掉，网站直接消失，严重的话域名会被抢注。注册商一般会提前发邮件，但那封邮件很容易被当成垃圾邮件忽略。给自己的域名设个日历提醒。

九、几个常识性误区

  • "域名就是网站。" 不是。域名只是名字，网站是跑在服务器上的程序。域名可以指向空服务器，也可以随时换指向。
  • "买了域名就有网站了。" 不是。域名 + 服务器 + 网站内容，是三件事。
  • "DNS 生效是瞬间的。" 不是。受 TTL 和各层缓存影响，全世界生效可能要几小时。
  • "用 IP 访问更快。" 通常反而更慢甚至失败——因为 HTTPS 证书绑定域名、服务器上可能有多个网站共用同一个 IP（靠域名区分），不报域名对方不知道你要哪个。
小结。域名是给人记的别名，DNS 是那本电话簿，TTL 决定这本簿子的信息多旧。搞清楚这三件事，网页打不开时你就有了一个明确的分诊思路——先 ping 域名能不能解析出 IP，能解析就是后面的问题，解析不出来就查 DNS。
